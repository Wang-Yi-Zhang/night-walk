# 夜行・線上報名

夜間生態觀察活動的報名網頁。

- **網頁**：https://wang-yi-zhang.github.io/night-walk/ （GitHub Pages）
- **資料**：你自己的 Google 試算表。透過 Apps Script 讀寫，聯絡方式（手機、LINE ID、IG）不會離開試算表。

```
報名者手機 ──▶ GitHub Pages 網頁 ──▶ Apps Script（以你的身分執行）──▶ Google 試算表
                    ▲                         │
                    └── 人數、暱稱（不含聯絡方式）──┘          └──▶ 寄通知信給你
```

---

## 一、第一次部署（約 10 分鐘）

### 1. 建立試算表
1. 到 [Google 試算表](https://sheets.new) 建立一份新的試算表，命名為「夜行報名」。
2. 點選上方選單 **擴充功能 → Apps Script**。

### 2. 貼上程式碼
1. 刪除 Apps Script 編輯器裡原本的 `function myFunction() {...}`。
2. 打開本 repo 的 [`apps-script/Code.gs`](apps-script/Code.gs)，**全選複製**後貼上。
3. 按 💾 儲存。專案名稱可以取「夜行報名」。

### 3. 執行初始化並授權
1. 在上方工具列的函式下拉選單選擇 **`setup`**，按 **▶ 執行**。
2. 跳出「需要授權」時，按 **審查權限**，選擇你的帳號（hemoparasite@gmail.com）。
3. 看到「**Google 尚未驗證這個應用程式**」是正常的，因為這個應用程式就是你自己建立的。按左下角 **進階**，再按 **前往「夜行報名」（不安全）**。
4. **確認權限清單只有以下三項**，再按「允許」：
   - 查看及管理已安裝此應用程式的試算表
   - 以你的名義傳送電子郵件
   - 連線至外部服務（只用來向 Cloudflare 確認防機器人驗證）

   > ⚠️ 如果清單出現「讀取 Gmail」、「查看、編輯、建立及刪除你在 Google 雲端硬碟中的所有檔案」等其他權限，**請按取消並告訴 Claude**。
5. 回到試算表，應該會看到「**設定**」和「**報名**」兩個分頁。重新整理試算表後，上方會出現「**🔦 夜行報名**」選單。
6. 在「設定」分頁填好本場的**場次代碼、場次標題、活動日期、報名截止**（初始化時這幾項是空白），確認其他項目後，把「**報名開關**」改成「開」。新試算表的報名開關預設是「關」，填好之前不會有人報名進來。

### 4. 部署成網頁應用程式
1. 在 Apps Script 右上角按 **部署 → 新增部署作業**。
2. 點「選取類型」旁的 ⚙，選 **網頁應用程式**。
3. 設定：
   - 說明：`v1`
   - 執行身分：**我（hemoparasite@gmail.com）**
   - 誰可以存取：**所有人**（不是「所有已登入 Google 帳戶的使用者」）
4. 按 **部署**，複製「網頁應用程式」的網址。網址開頭是 `https://script.google.com/macros/s/`，結尾是 `/exec`。
5. **把這個網址交給 Claude**，由 Claude 接上網頁並做實際報名測試。如果要自己接，就把網址貼到 [`config.js`](config.js) 的 `apiUrl`。

### 5. 啟用防機器人驗證（建議）
沒做這一步也能報名，只是任何人都能直接打後端網址灌報名。請照順序做，任何一步出問題，報名都不會中斷：

1. 到 [Cloudflare](https://dash.cloudflare.com/) 註冊（免費），左側選 **Turnstile → 新增小工具**。
   - 主機名稱：`wang-yi-zhang.github.io`
   - 小工具模式：**受管理（Managed）**
2. 建立後會拿到兩把金鑰：
   - **網站金鑰（site key）**：公開的，交給 Claude 貼到 [`config.js`](config.js) 的 `turnstileSiteKey`，推上 GitHub。
   - **密鑰（secret key）**：**不要貼給任何人、不要放進試算表或 GitHub**。
3. 確認新網頁已經上線後，到 Apps Script 左側 **⚙ 專案設定 → 指令碼屬性 → 新增指令碼屬性**：
   - 屬性：`TURNSTILE_SECRET`
   - 值：貼上密鑰
4. 用手機（包括從 LINE 點開）實際報名一次，確認成功。

**要停用驗證**：刪掉 `TURNSTILE_SECRET` 這個指令碼屬性就會立刻停用，不用重新部署。

## 二、日常管理（都在試算表裡操作）

「報名」分頁的欄位：`報名時間 | 場次代碼 | 暱稱 | 手機 | LINE ID | IG 帳號 | 身分 | 給主辦的話`。
報名者的手機、LINE ID、IG 帳號至少會填一項。程式是依**標題文字**找欄位，你可以調整欄位順序或插入自己的備註欄，但**不要改標題文字**。


| 想做的事 | 怎麼做 |
|---|---|
| 看名單 | 「報名」分頁。每筆報名也會寄 Email 通知你 |
| **有人取消** | 在「報名」分頁**刪除那一列**（或把「身分」改成「取消」） |
| **遞補候補** | 先聯絡候補者確認能來，再把他的「身分」從「候補」改成「正取」 |
| **加開名額** | 「設定」分頁把「正取上限」調高，再依序把候補改成正取。候補不會自動變成正取 |
| **因雨取消／延期** | 「設定」分頁把「活動狀態」改成「因雨取消」或「延期」，「狀態補充說明」可以寫原因或新日期。網頁會出現橫幅並停止報名 |
| 提早截止 | 「設定」分頁把「報名開關」改成「關」，或修改「報名截止」 |
| 網頁人數沒更新 | 網頁最多會延遲 30 秒。急的話點選單 **🔦 夜行報名 → 立即更新網頁人數** |
| 確認設定有沒有填錯 | 填錯的格子會變紅色，「設定」分頁最右邊的「**檢查**」欄會寫出原因。也可以點選單 **🔦 夜行報名 → 檢查設定** 一次列出所有問題 |

> 「設定」分頁的日期請照格式填寫：`2026-10-23`、`19:00`、`2026-10-23 12:00`（台灣時間）。

> 📋 **改期或辦下一場時，請照 [CHECKLIST.md（活動異動確認表）](CHECKLIST.md) 逐項檢查。**

### 辦下一場
1. 在「設定」分頁修改：**場次代碼**（換一個新的，例如新日期）、場次標題、活動日期、時間、報名截止，並把活動狀態改回「正常舉行」、報名開關改回「開」。
2. 網頁會自動切換成新場次，人數從 0 開始算。舊場次的報名紀錄會保留在「報名」分頁。
3. **LINE 分享預覽圖、標題和行事曆檔是寫死在網站上的**（LINE 和 iPhone 不會讀取試算表）。改完試算表後，請 Claude 執行 `python tools/sync_event.py`，它會從試算表讀取活動資料，更新 `og.png`、`event.ics` 和 `index.html` 的分享文字。忘了的話，GitHub 每天早上 9 點的檢查會寄信提醒你。

### 個資清除（活動結束後一個月內）
- **🔦 夜行報名 → 清除舊場次的聯絡方式**：清除目前場次以外所有場次的手機、LINE ID、IG 帳號。
- **🔦 夜行報名 → 清除所有聯絡方式（含目前場次）**：活動結束後，如果還沒開下一場，就用這個。

暱稱和報名紀錄會保留，只有聯絡方式會被改成「（已刪除）」。

## 三、修改程式後重新部署

修改 `Code.gs` 後，先在本機跑一次後端測試（需要 Node.js 22 以上，不用安裝任何套件），全部通過再部署：

```bash
npm test
```

推上 GitHub 後，GitHub Actions 也會自動跑一次，結果顯示在 commit 旁邊（綠勾或紅叉）。

要更新部署才會生效，而且**網址不會變**：

**部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**

> 不要按「新增部署作業」，那樣會產生新網址，網頁就會連不到。

部署完成後，**重新整理試算表**，選單才會換成新版。如果這次更新新增了欄位，請再點一次 **🔦 夜行報名 → 初始化／補齊工作表**，新欄位會自動插入，既有資料不受影響。

## 四、資訊安全

| 項目 | 做法 |
|---|---|
| Google 權限範圍 | `@OnlyCurrentDoc`：只能存取這一份試算表。用 `MailApp` 寄信：只能寄信，不能讀信。用 `UrlFetchApp` 只連到 Cloudflare 驗證 |
| 寄信對象 | 收件人寫死在程式碼裡（`NOTIFY_EMAIL`），外人無法利用它寄信給別人 |
| 聯絡方式 | 公開 API 只回傳人數和暱稱，永遠不回傳手機、LINE ID、IG 帳號 |
| 灌票、洗版 | 同一個手機、LINE ID 或 IG 帳號只能報一筆；每場最多寫入「正取上限 + 候補上限」筆；honeypot 和 Cloudflare Turnstile 防機器人（沒通過的請求不寫入、不占名額）；全站每分鐘最多 20 筆 |
| 公式注入 | 所有使用者輸入都以純文字（`'` 前綴）寫入試算表 |
| 網頁 XSS | 暱稱一律當純文字顯示 |
| 同時送出 | 寫入時加鎖，不會超收 |

**想停用或撤銷授權時：**
- 停用網頁：Apps Script → 部署 → 管理部署作業 → 封存
- 撤銷授權：[Google 帳戶 → 第三方存取權](https://myaccount.google.com/permissions) → 找到「夜行報名」→ 移除存取權

## 檔案說明

| 檔案 | 用途 |
|---|---|
| `index.html`、`style.css`、`app.js` | 報名網頁 |
| `calendar-time.js` | 加入行事曆的時間規則（沒填結束時間時怎麼算），跟 `tools/sync_event.py` 用同一份測試案例 |
| `config.js` | Apps Script 網址、Turnstile 網站金鑰 |
| `apps-script/Code.gs` | 後端程式（複製到 Apps Script 用，GitHub Pages 不會執行它） |
| `tests/` | 後端測試：在 Node 裡用假的 Google 服務載入 `Code.gs`，只透過對外介面驗證報名規則，並比對 `mock-api.js` 的規則是否一致。執行 `npm test`。`tools/sync_event.py` 的測試另外執行 `python -m unittest discover -s tests -p "test_*.py"` |
| `package.json` | 只用來放測試指令 `npm test`，沒有任何套件依賴 |
| `.github/workflows/test.yml` | 每次推上 GitHub 時自動跑測試 |
| `.github/workflows/event-check.yml` | 每天台灣時間 09:00 比對試算表和預覽圖、行事曆檔，並確認正式後端部署的是最新的 `Code.gs`；對不上時 GitHub 寄信通知 |
| `mock-api.js` | 本機預覽用的假資料：網址加 `?mock`、`?mock=wait`、`?mock=full`、`?mock=rain`、`?mock=deadline`、`?mock=notice`、`?mock=captcha`（驗證一律沒通過）。再加 `&turnstile` 可用 Cloudflare 的測試金鑰試用驗證 |
| `tools/sync_event.py` | 從試算表的公開資料重新產生 `og.png`、`event.ics` 和 `index.html` 的分享文字；加 `--check` 只檢查是否過期 |
| `og.png` | LINE 分享預覽圖（畫圖的程式在 `tools/make_og.py`） |
| `event.ics` | iPhone／Android「加入行事曆」用的檔案（產生的程式在 `tools/make_ics.py`）。日期時間跟試算表不一致時，網頁會自動隱藏這顆按鈕。要關閉按鈕，把 `config.js` 的 `appleCalendar` 改成 `false` |
| `CHECKLIST.md` | 改期或辦新場次時的確認表 |
| `SPEC.md` | 規格書：使用者故事、報名規則、API 合約、測試決策、已知風險 |
| `GLOSSARY.md` | 用語定義（場次、正取、候補優先、遞補……） |
| `docs/adr/` | 設計決策紀錄：為什麼這樣做、考慮過哪些做法 |
